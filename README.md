# BoloVerse

Photo → spoken instruction → generated product video, in one mobile web page. The current plan is at the top of [CLAUDE.md](CLAUDE.md); the VR studio was dropped.

**Status: milestone A.** You can upload a product photo, have its background removed in the browser, pick one of 8 preloaded backgrounds, set motion/speed/duration/colour grade by hand, preview the animated 9:16 composition, and record a webm (optionally with live mic narration). The video is saved to Supabase and shown as a player, a download link and a QR code. Voice control arrives in B.

## One-time setup

You need Node 20+ and a free [Supabase](https://supabase.com) account. The Supabase CLI is a dev dependency, so run it with `npx supabase …`.

1. **Install:** `npm install`
2. **Create a Supabase project** in the dashboard. Note the *Project ref* (the `xxxx` in `https://xxxx.supabase.co`).
3. **Enable anonymous sign-ins:** Dashboard → Authentication → Sign In / Providers → turn on **Allow anonymous sign-ins** → Save.
4. **Link and push the schema:**
   ```sh
   npx supabase login
   npx supabase link --project-ref <your-ref>
   npx supabase db push
   ```
   Or paste `supabase/migrations/0001_init.sql` into Dashboard → SQL Editor → Run. This also creates the private `products` and `reels` buckets.
5. **Edge Function secrets** (not needed for milestone A): copy `supabase/functions/.env.example` to `supabase/functions/.env` and fill in `SARVAM_API_KEY`, `GEMINI_API_KEY` and `GEMINI_MODEL`. They can stay empty for now. Then run:
   ```sh
   npx supabase secrets set --env-file supabase/functions/.env
   ```
6. **Deploy the functions:**
   ```sh
   npx supabase functions deploy
   ```
   This deploys `stt` and `tts` (skeletons for now; not needed for milestone A). If it complains about Docker, add `--use-api`.
7. **Frontend env:** copy `.env.example` to `.env`. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` from Dashboard → Project Settings → API (the *anon / publishable* key, never the service-role key).

## Run locally

```sh
npm run dev      # http://localhost:5173  (also printed with your LAN IP)
npm test         # unit tests
npm run build    # production build into dist/
```

## Deploy (Vercel)

1. Push this repo to GitHub and import it in Vercel. `vercel.json` already sets the Vite build and the `dist` output.
2. In Vercel → Settings → Environment Variables, add `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` and, optionally, `VITE_FUNCTIONS_URL`. Then redeploy.
3. Set the CORS allow-list on the functions (recommended before the demo):
   `npx supabase secrets set ALLOWED_ORIGINS=https://<your-app>.vercel.app,http://localhost:5173`

## Testing on an Android phone

The mic, motion sensors and Wake Lock only work in a **secure context**, meaning HTTPS or `localhost`. A phone opening `http://192.168.x.x:5173` is *not* secure. Use one of these:

- **Vercel URL (easiest):** open `https://<your-app>.vercel.app/` in Chrome on the phone.
- **USB port forwarding:** turn on USB debugging on the phone and plug it in. On the laptop, open `chrome://inspect/#devices` → *Port forwarding* → add `5173` → `localhost:5173` and tick *Enable port forwarding*. Then open `http://localhost:5173/` on the phone.

Open `/check/` first: every row should show ✓.

### Background removal on phones
- On the first visit the 44 MB model downloads from the IMG.LY CDN (the top-right pill shows %). After that the browser caches it.
- It uses WebGPU when Chrome has it (pill says `GPU`), otherwise CPU (`CPU`). On a laptop CPU, one photo took about 26 s. If it takes more than 90 s or fails, the app uses the photo on a white card instead.
- `@imgly/background-removal` is **AGPL-3.0**. That is fine for a hackathon demo; check the licence before any commercial use.

### Known limits
- Chrome's MediaRecorder writes webm without duration metadata. Players may show the length only after playing to the end. Instagram/WhatsApp may need conversion to mp4.
- The fallback backgrounds are procedural SVGs. Drop photos into `public/backgrounds/` and point `file` in `src/app/backgrounds.js` at them to swap.

## Security & Privacy (DPDP-aligned)

- **Minimisation:** command audio is transcribed and discarded. Only the text transcript is logged. Reel audio is the creator's content and is stored privately.
- **No secrets in the browser:** Sarvam and Gemini keys live only in Edge Function secrets.
- **Access control:** RLS is on for every table; only a session's owner can read or write its rows and files. Each browser gets an anonymous user and one session.
- **Deletion:** deleting a session (creator only) cascades to its products, briefs, reels and logs.
- Videos are private and shared only through 24-hour signed URLs (the QR code).
- Background removal runs on the phone; the product photo is not uploaded for that step.
