# XR Phase 1 Implementation Plan

**Goal:** An authorized creator can create/open a project and launch a real desktop A-Frame studio with feature-detected immersive VR entry.

**Architecture:** Preserve the existing Next.js/Clerk/Neon/Drizzle application. A browser-only adapter owns one imperative A-Frame scene in a disposable same-origin iframe; React owns surrounding accessible controls. The realm contains upstream globals, styles and listeners. Project services remain renderer-independent. The separate original recording experiment continues to work.

**Tech stack:** Existing pinned Next.js16/React19/TypeScript5.9, A-Frame1.8 with its pinned super-three engine, pnpm11.12, Prettier, Vitest/PGlite and Playwright.

**Spec:** `docs/XR_IMPLEMENTATION_SPEC.md`. User explicitly directs implementation starting with Phase1; the supplied design resolves the primary architecture choices.

## Scope and decisions

- Keep Drizzle: existing checked-in migrations, tenant-aware repositories, PostgreSQL tests and typed JSON contracts are reusable. No Prisma or second database.
- Existing workspaces/memberships implement organization tenancy; existing Clerk subject IDs stay text. Phase1 needs no duplicate users/organizations tables. Project creation uses only the authenticated user's own workspace.
- Add real create/list/open/edit project behavior. Scene persistence/object editing is Phase2; no save button falsely promises it in Phase1.
- `/xr/[projectId]` loads authorized project metadata on the server; arbitrary URLs never expose private content. `/xr/preview` is a separate public capability lab with original sample content, explicitly not a connected project or saved scene.
- A-Frame's engine is isolated from the existing recorder's Three.js package. Use runtime-owned DOM, registration guards and disposal, not React-managed A-Frame entities.
- Use local canvas textures for spatial text to avoid runtime CDN font requests. Disable unneeded inspector/keyboard shortcuts and external assets.
- Enter VR only after secure-context/device capability success and a user gesture. Unsupported desktops retain the 3D scene. Real headset/controller acceptance remains unverified without hardware.
- Adopt pnpm with one lockfile; add scoped Prettier checks for new modules, and CI checks. Preserve legacy formatting where unrelated.

## Review focus

1. Invalid/cross-origin mutation input, forged workspace IDs, client edit attempts: strict route validation + server role checks with actual PostgreSQL regression tests.
2. Missing credentials: explicit setup screen and API denial; public preview contains no tenant data and no test-auth bypass.
3. StrictMode/HMR/navigation: one A-Frame scene/render loop; no late initialization into a detached mount, duplicate registrations or listeners.
4. Unsupported/rejected WebXR session: desktop remains usable, VR button reports exact capability/error; no fullscreen mislabeled immersive VR.
5. Untrusted project text and engine isolation: no injected HTML/A-Frame attributes; render bounded text with local canvases using AFRAME.THREE.
