## Evidence and classification

“Implemented and tested” describes an existing bounded behavior with checked-in tests and recorded local verification. “Partially implemented” means some requested behavior exists, with explicit gaps. “Mocked” applies only to clearly labelled examples/adapters. “Missing” means no functional workflow was found. “Blocked” marks an acceptance gate needing external configuration/hardware or a prerequisite service. A database table, provider interface or navigation label alone does not establish implementation.

Historical baseline: [progress tracker](../../context/progress-tracker.md) records `pnpm check` passing 14 tasks, 445 tests in 43 files and both production builds before integration; the merged baseline independently passed all 445 tests. The earlier application packaging recorded 43 production Chromium cases. Native core has 48 passing tests in nine suites, and the checked-in Xcode project compiled for a generic visionOS Simulator destination. [Native validation](../shape-studio/native-validation.md) separately records simulator interactions/RealityKit tests and the unresolved reopened-model accessibility assertion. These results are historical, not a fresh claim about this feature branch.

## Architecture, dependencies and security boundaries

The existing three-application split is functional: `apps/web` is the sole Next.js App Router backend and conventional portal; `apps/spatial-web` is the canonical R3F editor reached through same-origin `/workspace*` and `/spatial-static*`; `apps/visionos` is an independent SwiftUI/RealityKit Xcode app and Swift package. Keep these boundaries. The illustrative two-app layout in the new brief does not justify moving working applications again.

Actual dependencies include Next 16.4.6, React 19.2.9, strict TypeScript, Tailwind 4, Radix Slot, Lucide, TanStack Query, Zustand, React Hook Form, Zod 4, Drizzle, Clerk, Neon, AWS S3/R2 support, Three.js and A-Frame. R3F is consumed by spatial-web. Drei, Motion and an infinite-canvas library are not currently installed; adding them needs a concrete functional consumer. Native pins ClerkKit through the Xcode Swift package resolution; `ShapeStudioCore` has no npm dependency. The JS graph contains consumed scene/config packages; generated API/token directories remain neutral artifacts.

The source schema has 22 tables with migrations `0000`–`0005`: personal workspaces/members, projects/members, creative drafts, briefs/artifacts, sessions, assets/products, three scene representations, content versions, comments/decisions, grants, command logs/claim checks, processing jobs/upload events and durable rate budgets. It has no full Organization/Client/BrandKit/Campaign/Task/Milestone/GenerationOutput/Moodboard/Deliverable service. Add these only with their functional slice, lifecycle, authorization tests and reviewable migration; schema noun parity is not a foundation requirement.

Existing protections to preserve:

- Server-only Clerk identity, database/provider credentials and storage access. SQL predicates authorize reads and mutations; browser-provided roles or IDs never establish access. Personal ownership is not complete Clerk Organizations support.
- V1 native bearer verification accepts only verified Clerk session identity/issuer; an invalid supplied Authorization header never falls back to cookies. Cookie mutations require an exact allowed Origin. Browser Origin is still checked when present on bearer transport. Strict Zod inputs and bounded streaming JSON prevent extra properties and oversized mutation bodies.
- Drafts are private to project **and author**, with atomic revision checks and durable save budgets. Canonical scenes validate same-project ready assets and revision CAS. Project creation is rate-limited. Existing output/decision immutability must not regress.
- Authenticated bounded private R2 reads expose safe transport metadata and relative content routes, never raw storage keys. A read proxy does not implement upload signing/finalization. No public test-auth bypass belongs in runtime code.
- Gemini/Sarvam **XR** adapters perform actual server requests when configured and are covered by fixture tests. The generic M0 registry is intentionally failure-only. Configuration/readiness and local development mocks do not prove live provider acceptance. No complete media-generation pipeline exists.

Open security/production gates include organization-aware administration, complete upload verification/finalization, generation job idempotency/output provenance/recovery, native USD decoding memory/complexity hardening, deployed membership revocation and private storage checks, real authentication registration and live-service validation. These are scoped gaps, not evidence that the existing implemented authorization checks can be bypassed.

Shared strict Zod contracts in `apps/web/src/lib/contracts` generate OpenAPI 3.1 and TypeScript/Swift models/routes through `scripts/generate-contracts.ts`; native copies are checked by `native:check`. `@shape/scene-schema` is renderer/server independent. Its frozen wire document is `{sceneId, version: 1, objects}`, with metres, right-handed +Y up, −Z forward and unit XYZW quaternions. Save revision is separate. Do **not** replace it with the brief's illustrative `schemaVersion/projectId/units/coordinateSystem` document without a separately versioned migration. Legacy A-Frame Euler layouts and recording state remain distinct.

Deployment is configured, not newly live-verified: the root launcher manages both Next apps, web owns the same-origin gateway, and path-aware GitHub Actions runs the JS graph/browser cases independently from Swift contract/core/simulator-build gates. No deployment, remote CI run, provider account capability or live migration is established by inspecting this configuration.

## Native preservation gates

Keep `apps/visionos` functional and independent during this web increment. `AppDependencies` owns one session observation task; account changes clear private project/draft/model state and invalidate/cancel API requests. `ClerkAuthenticationService` obtains tokens on demand, uses Clerk-owned Keychain credentials, persists only sign-out intent and guards late authentication completion. `APIClient` rejects redirects/changed URLs, bounds responses and retries authentication once without cookies. Preserve cancellation and generation checks after every private async result.

`ProductVolumeView` owns one renderer lease and releases it on disappearance. Targeted drag/rotation/scale, native accessibility labels, volume geometry bounds, local USDZ preflight, asynchronous model load and canonical centering/fit mapping are implemented. Unique workspace/inspector/volume windows and explicit immersive entry/exit must remain. Avoid adding web renderer objects, raw tracking or microphone capture to native state.

For native/shared-contract/token changes, require `pnpm native:check`, Swift contract fixtures, all Swift core tests, checked-in Xcode simulator-target compilation and relevant native UI/RealityKit flows. A build is not simulator interaction or physical-device validation. The known model accessibility omission after close/reopen remains an explicit unresolved gate even though display capture confirmed rendering. Hosted Clerk registration/login/logout, live Neon/R2 access, physical Vision Pro comfort/gaze/pinch/accessibility/memory/frame pacing and adversarial USD decoding remain unverified.

## Acceptance for the authorized initial web increment

1. Reuse the current application/database/auth/contracts/tokens rather than resetting the foundation. Document concrete additions and remaining gaps. Keep existing project, spatial, XR and recording URLs functional.
2. Deliver a coherent, responsive creative studio with usable prompt controls, local reference preview/editing/export and real loading/empty/error states. Preserve per-mode text and explicit private draft persistence. Keep illustrative/local content distinguishable from generated/server history; never invent jobs, metrics or approvals.
3. Connect any newly enabled action end to end through validated authorized services and focused behavioral tests. Unsupported generation/upload/review/publish actions remain honestly unavailable. Provider credentials alone cannot enable a creation feature.
4. Preserve keyboard navigation, visible focus, reduced motion, labelled controls, narrow-viewport reachability and unsaved-work handling. Local media/prompt state must not leak into browser persistence; release owned URLs/streams/renderers on teardown.
5. Before reporting implementation complete, run the full `pnpm check` graph, relevant production browser flows and any necessary separate native/contract gates. Record actual results for this branch separately from the historical baseline, plus external/live/device limits. Commit only reviewable source/docs/lockfile/migrations that were actually changed; exclude credentials, generated build output and user-generated concept output.

## Later roadmap
