## API and persistence boundaries

JSON endpoints under `/api/v1/workspace` expose overview, project collection/detail/update/duplicate, task create/update, clients and asset metadata. `/api/v1/brainstorm/sessions` exposes actor-private session collection/detail/update, messages and ideas. Shared schema registry, generated TypeScript/OpenAPI and synchronized Swift artifacts describe the JSON operations.

Binary operations remain explicit raw-body routes outside the current JSON-only client generator:

- `POST /api/v1/workspace/recordings?projectId=UUID&idempotencyKey=UUID`: video/webm or video/mp4, maximum 20 MiB.
- `POST /api/v1/workspace/uploads?projectId=UUID&idempotencyKey=UUID`: supported PDF, GLB/glTF, PCM WAV or video, maximum 20 MiB; existing image upload/reserve/finalize path remains independent.
- `GET /api/v1/workspace/assets/UUID/download`: authorized bounded attachment with no-store/nosniff and safe filename; no object keys or unrestricted signed storage URLs.
- `POST /api/v1/brainstorm/sessions/UUID/transcribe`: consent-gated transient recording, bounded existing Sarvam media/language contract, no raw audio persistence.

Creation commands use strict local action data and the existing authorized creative-draft CAS and Brainstorm endpoints. Unknown commands never execute; asset IDs resolve against an authorized same-project list. Scene/review commands open the existing workflow, and review requires explicit confirmation and later version/reviewer selection. “Change duration” only updates a labeled planning target. Saved production notes use the private video prompt and preserve other modes. Gemini captions require a successful real provider response and remain reviewable drafts.

SQL migration `0010_strange_sleeper.sql` adds seven tables and project metadata/revision/timestamps with foreign keys/indexes and preserves existing project creation dates on backfill. The complete schema has 31 tables. It does not duplicate project, asset, brief, version, review or identity models. Failed/permission-revoked storage staging may require reconciliation; it is never exposed as a ready asset. No live schema migration, cloud write, seed, account creation or provider request was performed.

Swift generation now accepts JSON-schema default annotations and preserves optional-nullable PATCH semantics through generated `ShapeNullable`: omitted means unchanged, explicit null means clear. 40 bidirectional fixtures include both cases. Existing strict canonical scene v1 is unchanged.
