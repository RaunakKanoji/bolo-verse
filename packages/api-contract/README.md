# Shared API contract

`src/lib/contracts/shape.ts` defines strict runtime Zod schemas and route metadata. `scripts/generate-contracts.ts` publishes OpenAPI 3.1 to `openapi.json`, then generates TypeScript DTOs/client methods and Foundation-only Swift Codable/Sendable DTOs/relative route paths from that exact serialized artifact.

Run `pnpm contracts:generate` after a schema change, then `pnpm contracts:check`. The check compares every artifact without writing. `pnpm contracts:test:swift` typechecks the generated Swift and exercises real JSON decode/encode fixtures using the installed Swift compiler; it is an explicit check so web-only environments do not silently claim native validation.

The generator deliberately supports only closed objects, homogeneous arrays, component references, string/integer enums, boolean literals, required nullable fields and scalar constraints. Unrecognized keywords, arbitrary dictionaries, unions other than nullability, and optional nullable fields fail generation rather than silently widening types. Bounds, formats and patterns are published in OpenAPI and validated by the server's Zod boundary; generated DTOs are transport representations, not complete client-side validators. Swift decoding additionally rejects unknown object keys and invalid enum/literal values and preserves required JSON nulls.

The TypeScript client uses same-origin browser sessions and throws `ShapeApiError` for structured HTTP failures. It does not turn its response types into runtime validation. Swift routes contain no secrets, networking or authentication shortcuts; native URLSession and Clerk integration belongs to Phase 6. Only implemented JSON endpoints are published. Binary authorized asset content responses are intentionally outside the generated JSON client. `AssetSummary.contentUrl` is a required nullable URL for the bounded browser-preview reader, not a general download endpoint; unsupported MIME types or assets over 20 MiB have no URL. Successful content validation and authorization are still required when following a non-null URL.

All dates are ISO strings rather than platform-default Date encodings, so timestamp spelling is preserved across clients. Integer DTO fields use Swift Int64; their server bounds stay within JavaScript's safe integer range. No native app or physical-device compatibility follows from contract compilation.
